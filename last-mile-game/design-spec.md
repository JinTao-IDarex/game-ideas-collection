# 「最后一公里」游戏原型 · 设计 Spec（三方向共同输入）

## 产品是什么
一款单关 HTML 可玩原型游戏：玩家扮演早高峰打工人，要在 **5 分钟倒计时** 内完成「找共享单车 → 验车/选车 → 开锁 → 骑行 → 到公司打卡」的全流程。核心乐趣来自**车况盲盒**（可见损伤 vs 隐形损伤）与**时间压力下的决策**（闯红灯？换车？忍痛骑？）。

## 本次三方向初稿的范围
每版只做**一个核心画面：找车/选车阶段**（俯视街区地图 + 车辆标记 + 选中车辆的详情卡 + 顶部 HUD），但必须是**真实可点击的 HTML**——点击地图上的车辆标记，详情卡切换到对应车况。三版同内容、同文案、同数据，只换设计逻辑。

## 目标受众与使用场景
- 年轻打工人 / 游戏玩家，对共享单车通勤窘境有强共鸣
- 桌面浏览器打开，1440×900 视口截图评审
- 气质：幽默、扎心、有点丧但不绝望（"笑着流泪"）

## 核心信息与内容要点（三版统一）
1. **HUD**：倒计时 04:32、体力、心情三个状态；本关目标「09:00 前打卡」
2. **街区地图**：家（起点）、公司（终点，东北角）、道路网、6 辆单车散布
3. **车辆标记**：大部分显示「?」（车况未知 = 盲盒感），少量露出 1 个可见特征；每辆标注步行秒数
4. **车辆详情卡**（点击切换）：侧视单车图 + 车况标签（可见损伤直接标出：无坐垫 / 无把手 / 坐垫湿；隐形损伤不标但留视觉线索：链条松垮、刹车线断裂、坐垫水渍反光）+「步行前往」按钮
5. **6 辆车的统一数据**（三版共用）：
   - A 车：步行 20s · 可见完好 · 隐形：刹车失灵（线索：刹车线垂落）
   - B 车：步行 35s · 可见：无坐垫
   - C 车：步行 45s · 可见：完好 · 隐形：链条断（线索：链条松垮下垂）
   - D 车：步行 60s · 可见：坐垫湿（线索：坐垫反光水渍）
   - E 车：步行 75s · 可见：无把手
   - F 车：步行 90s · 可见：完好 · 无任何隐形损伤（"好车"，但最远）

## 情感基调关键词
扎心幽默 / 通勤焦虑 / 盲盒赌运气 / 市井烟火气

## 输出格式与尺寸（三版统一）
- 纯 HTML/CSS 单文件（少量原生 JS 做车辆点击切换），无生图
- 1440×900 桌面视口；截图 `npx playwright screenshot --viewport-size=1440,900`
- 存放：`last-mile-game/design-demos/[方向名].html`
- 单车图形用 CSS/SVG 绘制（这是游戏美术本身，非 imagery 占位）

## 图片需求判断（Phase 3.5）
**图片非内容必需**：这是工具/游戏型产出，画面即界面，单车与地图用 CSS/SVG 绘制就是内容本身，无照片级素材需求。不取图。

## 视觉母题假设
- 母题 1：**盲盒卡片**——每辆单车是一张未拆的卡，「?」标记是核心视觉符号
- 母题 2：**打卡计时器**——04:32 这种精确到秒的红色倒计时是情绪发动机
- 母题 3：**手机找车 App**——地图阶段模拟真实找车 App 的 UI 质感，让玩家秒代入

## 已知约束
- 无品牌资产、无指定风格 → 走三方向流程
- 反 slop 底线：不用紫渐变 SaaS 风、不用 emoji 充当游戏美术、正文 ≥14px、对比度 ≥4.5:1
- 三版布局骨架必须互异（侧栏式 / 全幅地图+底部抽屉式 / 玩具卡片式）
